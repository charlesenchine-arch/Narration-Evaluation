# API 家族偏好预实验：20 题 Prompt 包与执行记录

版本：2026-08-24 v1  
用途：仅用于工程预实验与假设筛查，不作为论文最终冻结测试集。

## 1. 本轮冻结设置

- 生成器与评测器使用同三个家族：`deepseek-v4-pro`、`gemini-3.5-flash-lite`、`grok-4.20-0309-non-reasoning`。
- 每个模型为每个 Prompt 生成 1 篇文本：20 题 × 3 模型 = 60 篇机器文本。
- 加入已有的 20 篇 COIG 人类参考文本，共 80 篇候选文本。人类文本在本轮不重新创作。
- 三个模型分别盲评全部 80 篇文本；每篇、每位裁判都是一个独立 API 请求：`80 × 3 = 240` 次正式评分。
- 每次评分返回总分、置信度、6个基础诊断维度和简短理由；不向裁判显示作者或模型来源。
- 全部请求使用全新单轮上下文，不传历史消息、记忆、工具或搜索能力。
- DeepSeek：`thinking.type=disabled`；Gemini：`thinking_level=minimal`；Grok：使用 non-reasoning 模型。本轮 API 返回的可见 reasoning token 均为 0。
- 不为任何模型启用 Web Search、grounding、浏览器、文件检索、代码执行或函数工具。
- 同一模型在生成和评测阶段使用同一模型标识与最低推理设置；生成和评测分别使用不同的全新会话。
- 保存请求模型、实际返回模型、时间、request ID、输入/输出/推理 token、原始输出、解析状态和重试原因。

## 2. 长度规则与失败处理

字数统一定义为“非空白字符数”：删除空格、制表符和换行后，汉字、字母、数字及标点符号均各计 1 个字符。所有 Prompt 统一要求 500—1200 字符；本轮工程 QC 在校准后对上限使用 3% 计数容差，即最高 1236。

机器输出不能靠人工截断，也不能从多个候选中挑最好的一篇。预注册流程如下：

1. 首次请求直接使用下方完整 Prompt。
2. 本地程序按上述规则计数；合格则立即锁定该首个合格输出。
3. 预设流程最多允许 3 次只针对长度的自动纠偏；每稿、实测字符数和失败原因全部留档。
4. 本轮在工程校准期间有 3 篇超过上述上限，最多使用了 10 个总草稿才达标。因此本轮只能作为 pilot，不能冒充论文预注册测试。
5. 主分析使用首个合格输出；附录同时报告各模型首轮合格率、重写率和无效率，并以所有第一稿做敏感性分析。

模型的“输出前自行核对”只是降低失败率，最终是否合格只由本地字符计数器决定。

| DeepSeek | 133 | 127707 / 48446 | $0.0977（按公开单价估算） |
