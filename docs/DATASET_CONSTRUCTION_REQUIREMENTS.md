## 1. 数据集究竟要证明什么

数据集服务于一个核心问题：**叙事质量评估器能否依据作品质量，而不是依据“像人写的”或“像某个生成器写的”来判断作品。**

因此，数据集必须让“来源”和“质量”可以交叉：既要有高质量与低质量人类文本，也要有高质量与低质量机器文本。人类文本不能天然视为高质量，机器文本也不能天然视为低质量。

数据集不用于：

- 训练普通人机文本检测器；
- 证明机器写作普遍优于或劣于人类；
- 把某个开源 Judge 的输出当作文学质量真值；
- 声称文学作品存在唯一、完全客观的绝对分数。

论文主监督是**盲态下的人类成对总体质量偏好**。连续分、ABCDF 等级、维度标签和评语是对偏好关系的压缩与解释，不取代人类偏好数据。

## 2. 不可妥协的七条原则

1. **质量标签与来源标签分开产生。** 先隐去来源做人类质量盲评，再根据盲评结果划分质量层级。
2. **来源与质量必须有充分重叠。** 正式数据必须能构成 `H_high`、`H_low`、`M_high`、`M_low` 四个区域。
3. **跨来源比较必须控制表面混杂。** 同一比较尽量匹配主题、体裁、Prompt 语义和长度；尤其不能让长度直接暴露来源。
4. **生成过程不可挑最好的一篇。** 使用预先冻结的生成参数、重试规则和“首个合格输出”规则，所有失败都保留日志。
5. **切分按作品和 Prompt 分组。** 同一作品、Prompt、改写版本和近重复文本不能跨训练、开发、测试集。
6. **先 pilot、过门槛、再扩容。** 若质量没有重叠、人工一致性不足、长度仍泄漏来源或授权不清，不得直接扩大到 2,000 篇。
7. **外部训练池与自建实验池物理隔离。** 外部已有数据用于训练和开发；我们预先冻结 Prompt 后采集的同 Prompt 人机文本只用于实验，绝不进入模型训练、阈值选择或调参。

## 3. 数据组织单位

### 3.1 Pool A：外部训练混池

Pool A 接入已有数据集中的人类与机器文本，用于训练和开发。其数据组织可以沿用原数据集的 `work_id`、`prompt_id`、评分或 pair，但必须统一字段并保留来源。

仅有“人类/机器”来源标签的数据不能把人类自动当作高质量、机器自动当作低质量。只有原生质量评分、成对偏好或经过来源盲化的人类补标才能作为质量监督；来源标签只能用于探针、分组和去偏。

### 3.2 Pool B：自建同 Prompt 实验组

最终实验池的基本采集单位是一个在写作前冻结的 `prompt_group`：

- 1 个事先冻结的写作 Prompt 和长度层；
- 至少 1 篇、推荐 2 篇由独立作者根据该 Prompt 完成的人类文本；
- 至少 3 个不同生成器家族各生成 1 篇机器文本；
- 对应的来源私有元数据、生成日志、质检记录和盲评记录。

Pool B 中人类和机器必须收到相同的核心 Prompt，双方都不知道另一方的文本。Pool B 只用于冻结实验，不得回流训练。

### 3.3 三种 Prompt 证据等级

| 等级 | 来源 | 可支持的结论 |
|---|---|---|
| A | 人类作者真实收到的原始 Prompt | 最强的同 Prompt 对照 |
| B | 数据集原有、且能确认与文本对应的 Prompt | 较强的同任务对照 |
| C | 根据人类成文反推的中性 Prompt | 观察性主题匹配，不支持严格因果表述 |

必须保存 `prompt_provenance` 和 `pairing_strength`，正式分析中分层报告，不得把 C 级反向 Prompt 描述成作者的真实写作条件。

## 4. 分池、分阶段规模

| 阶段 | 建议规模 | 人类标注 | 用途 |
|---|---:|---:|---|
| Pool A 工程诊断 | 当前 20 个反向 Prompt 组、约 80 篇文本 | 可先无 | 检查接口、格式、来源泄漏和模型运行链路 |
| Pool A 正式训练混池 | 约 1,000–3,000 篇有效文本、3,000–10,000 个训练/开发 pair | 使用原生质量标签并对关键无标签子集补标 | 训练模型、选择阈值与消融 |
| Pool B1 协议 pilot | 20–30 个全新同 Prompt 组 | 每个核心 pair 优先 5 人 | 冻结长度、标注、API 与样本量方案；不训练模型 |
| Pool B2 冻结实验 | 初步建议 80–120 个全新 Prompt 组 | 每个核心 pair 至少 5 人 | 论文主结果；不训练、不调参 |

当前 20 题来自外部人类文本和反向 Prompt，应定位为 Pool A 工程诊断或候选训练数据，而不是最终同 Prompt 实验。B2 最终规模由 B1 的一致性、效应大小和功效分析冻结。

## 5. 人类文本池构建要求

### 5.1 两个池的来源覆盖

Pool A 至少使用两个相互独立的外部人类文本渠道，例如：

- 许可清晰的现有数据集；
- 许可清晰的征文、编辑档案或公开作品库。

Pool B 仅使用根据预注册 Prompt 新招募的人类作者，不从 Pool A 搬运成文。不能只招募成熟作者，也不能为了制造低质量人类文本而故意破坏好作品。质量层级只能来自盲评。

### 5.2 当前短叙事主轨的纳入标准

- 中文完整短叙事；
- 当前主轨为 500–1,200 个中文字符；
- 能脱离上下文独立阅读；
- 具有基本人物、事件或状态变化，而非提纲、评论或说明文；
- 作者身份或来源可追溯；
- 授权状态、可否再分发和署名要求可记录；
- 不含不必要的个人隐私和敏感信息。

可以在未来增加其他长度轨，但必须单独建层、单独匹配和报告，不能把长短文本静默混在同一主结果中。

### 5.3 排除标准

- 网文或长篇作品的残缺切块；
- 续写片段、提纲、剧本、广告、演讲、评论、助手回复或创作说明；
- 模仿具体在世作者、复述著名作品或高度疑似复制的文本；
- 严重乱码、缺段、标题冒充正文；
- 无法核验人类创作来源的文本；
- 经 LLM 实质润色却仍被标为纯人类来源的文本；
- 授权不明且计划公开再分发的文本。

授权不明的材料可暂存为 `internal_review_only`，但不能进入公开发布包。每篇正式人类文本至少经过两名独立审核者检查；分歧由第三人裁决。

## 6. 反向 Prompt 构建要求

反向 Prompt 的目的只是让机器文本与人类文本处于相近主题和体裁，不是复刻原文。

本节只适用于 Pool A 的外部成文。Pool B 不使用反向 Prompt，而是在任何人类或机器写作发生前先冻结真实实验 Prompt。

合格 Prompt 可以包含：

- 宽泛主题；
- 体裁或叙事形式；
- 逐篇设定的目标长度范围；
- “独立设计人物、冲突、转折和结局”等通用要求。

不得包含：

- 原文专有人名与独特关系；
- 原文事件顺序、关键转折或结局；
- 原文标志性句子、罕见意象或独特设定组合；
- “模仿某作者”或“复述某作品”；
- 足以让模型重建原文的答案提纲。

每个 Prompt 由两人分别审核 `完整性匹配` 与 `情节泄漏`。若无法在不泄漏的情况下构造中性 Prompt，应排除该人类文本。生成任务必须绑定 `prompt_version` 与内容哈希，版本变化后不得与旧输出混为同一生成条件。

## 7. 机器文本生成要求

### 7.1 模型覆盖

正式 benchmark 至少覆盖 3 个独立生成器家族，而不是同一家族的三个小版本。模型家族、具体版本和推理设置均需记录。开启思考、关闭思考、不同推理强度应视为不同生成条件，不能混写成同一个模型。

### 7.2 统一生成协议

- 每次使用全新上下文；
- 不使用搜索、外部工具、项目记忆或人类原文；
- 只发送审核后的 Prompt；
- 保存服务端原始返回，不人工润色、不手动截断；
- 冻结 temperature、top-p、max tokens、reasoning 设置和系统提示；
- 记录请求模型与实际返回模型、日期、接口、token、请求状态和重试次数；
- 拒答、截断、越界和接口失败均保留原始记录。

### 7.3 长度控制按数据池区分

Pool A 的外部成文可以按每篇人类文本实际长度给机器文本设置逐篇目标范围，以形成观察性匹配。

Pool B 不得先看人类成文再修改机器 Prompt。每个 Prompt 的长度层必须在双方写作前冻结，例如 600–750、750–900 或 900–1,050 字；人类和机器收到相同范围。

校准 pilot 的默认要求：

- Pool A 核心 pair 的人机字符数差异默认不超过人类文本长度的 ±10%；
- Pool B 中双方首先都必须满足预注册长度层，再报告实际长度差并做匹配/分层分析；
- 若模型第一次越界，按预先冻结的相同规则重试；
- 最多重试次数在生成前写入配置；
- 采用“首个满足格式和长度的输出”，不得从多个合格结果中挑质量最高者；
- 所有越界原始输出保留为失败日志，不进入核心匹配集；
- 若固定重试后仍无法匹配，标记失败或进入单独长度层，不能人工删改正文。

正式扩容前，可以根据 B1 pilot 调整长度层和匹配阈值，但 B2 Prompt 冻结后不得修改。

### 7.4 禁止选择性采样

以下做法会破坏数据可信度：

- 人工从多次输出中选“最好的一篇”；
- 发现某个模型写得弱后临时提高其推理强度；
- 对某些来源重试，对另一些来源不重试；
- 删除拒答和失败而不留下记录；
- 为得到想要的 `H_low`/`M_high` 比例而手工修改文本。

## 8. 长度、主题与表面特征控制

跨来源核心 pair 必须满足：

- 同一个 Prompt 组或经过审核的语义匹配 Prompt；
- 同一体裁层；
- 主题一致但情节独立；
- 长度满足预注册阈值；
- 标题、格式、署名和平台套话统一隐藏；
- 不进行会改变内容质量的过度“风格清洗”。

每篇文本至少记录中文字符数、总字符数、token 数、段落数和句子数。扩容前必须运行简单来源探针：长度、段落数等表面特征不应轻易预测人机来源。

校准 pilot 的暂定通过条件是：

- Pool A 核心跨来源 pair 至少 90% 满足逐对 ±10% 长度匹配；Pool B 核心文本至少 90% 落入双方共同收到的预注册长度层；
- 仅用长度预测来源的分组交叉验证 AUC 建议低于 0.65；
- 若超过阈值，先修复匹配，再评估质量偏差。

`AUC < 0.65` 是 pilot 的暂定工程门槛，不是普适统计定理；应在查看正式测试结果前冻结最终阈值。

## 9. 去重、污染与可追溯性

### 9.1 去重

- 对规范化全文计算 SHA-256，执行精确去重；
- 使用字符 n-gram、MinHash 或等价方法执行近重复检测；
- 同一作品的不同切片、改写和版本共享 `work_id`；
- Prompt 也需要聚类，近重复 Prompt 不能跨切分；
- 机器输出若与人类原文高度相似，必须人工检查是否泄漏或复述。

### 9.2 污染说明

公开人类文本可能出现在大模型预训练语料中，无法承诺完全无训练污染。数据集必须记录作品公开时间、来源链接和知名度风险，并在论文中把它作为限制。对因果要求最高的子集，优先采用采集时间较晚、未公开或作者授权的新文本。

### 9.3 原始层与盲评层分离

至少维护三层数据：

1. **私有来源层**：来源、作者/数据集、授权、模型、接口和完整生成日志；
2. **盲评层**：只含随机 `blind_id`、正文和无来源提示的任务信息；
3. **发布层**：只包含可合法再分发的内容与必要的数据卡。

盲评者、质量模型和前端不得读取来源私有字段。

## 10. 人类盲评要求

### 10.1 标注顺序

每个 pair 按以下固定顺序标注：

1. 总体哪篇叙事更好：`-2/-1/0/1/2`；
2. 判断信心：1–5；
3. 最关键的固定核心维度；
4. 可选扩展维度；
5. 支持判断的 A/B 原文证据；
6. 一句比较理由。

总体偏好必须先问，避免评分者把总体质量机械理解为维度等权求和。评分页面不得显示来源，也不应询问“哪篇是 AI”。

### 10.2 评分者与重复数

- 校准 pilot：核心 pair 优先每对 5 人；
- 正式 benchmark：每对至少 3 人，关键反转与 near-tie pair 优先 5 人；
- 条件允许时同时招募普通读者和文学/编辑经验评分者，分群报告；
- 关键 pair 设置 A/B 换序复测；普通标注任务抽取 10%–20% 做换序或重复质控。

当前 20 题若每题包含 3 个人机 pair，共 60 个核心 pair；每对 5 人即需要 **300 次独立判断**。

### 10.3 评分者质控

- 使用少量预先审核的锚点；
- 检查重复和换序一致性；
- 阅读时长只作联合异常信号，不单独淘汰；
- 检查空白、复制和无文本证据的理由；
- 保留真实分歧，用软标签或后验分布表达不确定性；
- 剔除规则必须在查看模型主结果前冻结。

LLM Judge 可以作为辅助基线和成本估计工具，但不能代替人类盲评真值。

## 11. 从盲评得到质量层，而不是预设质量层

使用 Bradley–Terry、Thurstone 或等价成对比较模型，基于盲评得到每篇文本的质量后验与不确定性。再在开发阶段冻结分层规则：

- `H_high`：盲评后验较高的人类文本；
- `H_low`：盲评后验较低的人类文本；
- `M_high`：盲评后验较高的机器文本；
- `M_low`：盲评后验较低的机器文本；
- `near_tie`：差异不确定或后验接近 0.5 的比较。

不得为了四格平衡而修改人工标签。若某一格不足，应定向补采：例如增加更强的人类作品、降低机器生成条件、增加新 Prompt，或更换候选来源。

扩容前必须确认两类关键反转都真实存在：

- `H_low` vs `M_high`：模型若仅偏爱人类来源会失败；
- `H_high` vs `M_low`：阳性对照。

校准 pilot 建议每类关键反转至少覆盖 20 个相互独立的 Prompt 组，并在正式方案中冻结最终数量。若机器几乎总是胜过当前人类池，这说明当前样本缺乏质量重叠，不能据此直接研究来源偏差。

## 12. 配对矩阵

| Pair 类型 | 主要用途 | 是否进入主测试 |
|---|---|---|
| 同来源高 vs 低 | 测清晰质量区分能力 | 是 |
| 同质量人类 vs 机器 | 估计条件来源差 | 是，解耦核心 |
| `H_low` vs `M_high` | 反人类来源捷径 | 是，最关键 |
| `H_high` vs `M_low` | 阳性对照 | 是 |
| near-tie | 校准与不确定性 | 单列报告 |

A/B 位置必须随机化。冻结的反转测试集不得参与训练、阈值选择或 Prompt 修改。

## 13. 数据切分要求

- Pool A 只切为训练与开发，按下列分组规则用于模型选择；
- Pool B1 只用于实验流程校准，不训练模型；
- Pool B2 在模型、阈值和分析协议冻结后采集，整体作为独立测试；
- 主切分按 `work_id` 分组；
- 优先同时按 `prompt_id` 分组；
- 近重复作品和近重复 Prompt 作为一个泄漏簇切分；
- 跨训练/测试边界的 pair 直接丢弃；
- pair-random 只可用于代码冒烟测试，不能作为论文主数字。

正式测试至少包括：

1. 未见作品测试；
2. 一个完整生成器家族从未进入训练的 unseen-generator 测试；
3. 冻结的 `H_low` vs `M_high` 反转测试；
4. near-tie 校准测试。

资源允许时增加 unseen-genre 和 time split。

## 14. 最小字段规范

### 14.1 盲评可见字段

| 字段 | 含义 |
|---|---|
| `blind_id` | 与来源无语义关联的随机 ID |
| `work_id` | 作品与版本分组 ID |
| `prompt_id`、`prompt_version` | Prompt 组和版本 |
| `text` | 原始正文的规范展示版本 |
| `genre`、`topic` | 经审核的粗粒度体裁与主题 |
| `char_count`、`token_count`、`paragraph_count` | 表面统计 |
| `text_sha256` | 正文完整性与精确去重 |

### 14.2 仅私有来源层可见字段

| 字段 | 含义 |
|---|---|
| `source_type` | `human` / `machine` / `unknown` |
| `source_dataset`、`source_url` | 人类文本来源 |
| `prompt_provenance`、`pairing_strength` | Prompt 证据等级 |
| `generator_family` | 生成器家族 |
| `model_requested`、`model_returned` | 请求与实际模型 |
| `reasoning_mode`、`search_enabled`、`tools_enabled` | 生成条件 |
| `temperature`、`top_p`、`max_tokens`、`seed` | 可复现参数 |
| `api_base`、`request_id`、`created_at` | 请求审计信息 |
| `generation_status`、`retry_index` | 失败与重试 |
| `license_status`、`redistribution_tier`、`attribution` | 授权与发布级别 |
| `qc_status`、`exclusion_reason`、`reviewer_ids` | 人工审核轨迹 |

任何字段缺失都要显式为 `unknown`，不能用空值暗示“未发生”。

## 15. 扩容前 Go / No-Go 门槛

以下阈值是校准 pilot 的暂定执行标准，正式测试前冻结：

| 检查项 | Go 条件 | 失败后的动作 |
|---|---|---|
| 来源与授权 | 100% 可追溯；公开集均可合法分发 | 只保留内部或更换来源 |
| 文本完整性 | 正式候选均通过双人审核 | 排除或裁决 |
| 生成覆盖 | 至少 3 个生成器家族；失败和重试均有日志 | 补模型或修复接口 |
| 长度匹配 | 核心 pair 至少 90% 在 ±10% | 按逐篇长度重新生成 |
| 长度来源探针 | 建议 AUC < 0.65 | 不做质量偏差结论，先修匹配 |
| 人工标注 | 核心 pair 每对达到计划人数；重复/换序可靠性可接受 | 修订界面、指南或评分者培训 |
| 质量重叠 | 四格均有样本，且两类反转 pair 数量足够 | 定向补采，不改标签 |
| 去重与泄漏 | 无跨切分作品、Prompt 或近重复泄漏 | 按簇重新切分 |
| 论文价值 | 出现可复现来源偏差，或形成有统计把握的偏差上界/边界结论 | 调整问题或停止扩容 |

“未发现显著来源偏差”不等于没有论文价值，但必须有足够功效和窄置信区间，能说明偏差上界，而不是因为数据噪声太大而没有检出。

## 16. 当前 20 题数据按本规范的审计

当前汇总：20 个 Prompt、80 篇文本、60 个人机 pair、3 个机器生成条件；尚未收集人类盲评。

| 项目 | 当前状态 | 判断 |
|---|---|---|
| Prompt 组与流水线 | 20 组已跑通 | 通过工程诊断 |
| 机器条件 | Gemini 3.5、Gemini 3.6、DeepSeek 三种条件 | 可用于 pilot；正式集仍需确认“家族独立性”和版本 |
| 来源字段盲化 | pair 数据可盲评 | 基本通过 |
| 人类文本双人审核 | 尚未完成正式独立审核 | 未通过 |
| 授权与发布 | 部分来源仍为 `internal_review_only` | 未通过公开发布门槛 |
| 逐对长度 ±10% | 大量机器文本明显长于人类文本 | 未通过 |
| 长度来源探针 | AUC = 0.963 | 严重未通过；来源可被长度直接识别 |
| 人类盲评真值 | 0 次 | 未通过 |
| 质量重叠 | 两个本地代理 Judge 几乎都偏向机器文本 | 未确认；更可能说明当前人类池和长度未匹配 |
| 位置稳定性 | Qwen 20 对换序审计一致率 70%，且显示 A 被选 15/20 | 代理 Judge 存在明显位置敏感风险 |
| unseen-generator 测试 | 尚未冻结完整家族留出 | 未通过正式实验门槛 |

本地 reward model 在 60 对中选择机器 59 次，Qwen Judge 选择机器 53 次；这些结果只能说明**当前代理模型在当前不平衡样本上稳定偏向机器文本**。它们不能证明机器叙事普遍优于人类，也不能证明质量评估器存在来源偏差，因为：

- 人类候选池尚未经过正式质量筛选；
- 机器文本平均更长、更完整、更像经过统一润色；
- 长度本身已几乎暴露来源；
- 两个 Judge 都不是人类审美真值；
- 质量四格尚未构成。

所以当前数据的正确定位是：**成功的工程诊断 pilot，尚不是论文 benchmark。**

按双池协议，它应进入 `pool_a_engineering_pilot`；在补充可靠质量监督后可作为 Pool A 训练/开发候选，但不能进入 Pool B 最终实验。

## 17. 当前最短可执行路径

1. 将当前 20 题正式标为 `pool_a_engineering_pilot`，继续完成授权、完整性和质量监督审计。
2. 调研并接入多个带人类/机器文本的外部数据集，区分原生质量标签、需补标数据和仅来源标签数据。
3. 用 Pool A train/dev 训练模型，完成去偏方法、ABCDF 阈值和最终 checkpoint 选择。
4. 设计 20–30 个全新 B1 Prompt，在任何写作发生前冻结长度层、生成规则和标注协议。
5. 招募人类作者，并用 API 让至少 3 个生成器家族完成完全相同的 Prompt；B1 只校准实验流程。
6. 冻结模型、阈值、B2 Prompt、API 条件、主指标和统计代码。
7. 再采集 80–120 个全新 B2 Prompt 组，完成人类盲评，只做一次性论文主评估，不回流训练。

这条路径的核心是：**训练只看外部混池，最终结论只看从未进入训练的自建同 Prompt 实验池。**
