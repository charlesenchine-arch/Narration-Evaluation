## 一句话论文主张

我们研究的不是“能否识别人类文本”，也不是“能否生成一个看似精确的文学分数”，而是：**叙事质量评估器能否依据作品本身的质量而非人类/机器来源线索做出判断，并把这一能力泛化到未见作品和未见生成器。** ABCDF 等级、内部连续分、多维证据和评语用于呈现与验证判断，不是论文的主问题。

## 1. 核心科学问题

论文围绕四个可证伪问题展开：

1. 评估器给人类文本高分，是因为作品确实更好，还是因为识别出了“人类写作痕迹”？
2. 评估器给机器文本低分，是因为叙事存在缺陷，还是因为识别出了特定生成器口癖？
3. 把一篇经盲评确认的低质量人类文本与一篇高质量机器文本放在一起，评估器能否选对？
4. 换成训练中从未出现的新生成器后，质量判断是否仍然成立？

因此，**来源识别能力不是目标，甚至可能是一条需要测量和抑制的捷径**。只有当模型在控制人类质量之后不再系统偏爱某一来源，并能通过跨来源反转测试，才能说它预测的是质量。

## 2. 论文贡献与非贡献

### 2.1 主要贡献

- 一个来源与质量交叉平衡的中文叙事评估基准，包含盲评成对偏好、作品身份、提示、题材和生成器元数据；
- 一套质量—来源解耦诊断协议，核心包括跨来源反转、同质量来源差、来源泄漏探针和未见生成器测试；
- 一个由人类成对比较训练的叙事 reward model，并与开源通用 LLM Judge、专用 Judge/reward model 和轻量基线比较；
- 对模型质量判断的校准、泛化、证据忠实度和失败模式分析。

### 2.2 明确不是主要贡献

- 人机文本检测器；
- 单独的 0–100 打分网页；
- 声称存在唯一、客观的文学质量真值；
- 仅凭“模型评语像人”就宣称模型理解了审美。

## 3. 任务定义：先比较，后压缩为分数与等级

### 3.1 主监督：成对总体质量偏好

评分者在不知道来源、生成器和预设等级的情况下阅读文本 A/B，回答总体上哪篇叙事更好：`-2/-1/0/1/2`，分别表示 B 明显更好、B 略好、难分高下、A 略好、A 明显更好；同时报告信心。

总体判断必须先于维度问题。模型学习潜在质量效用 `s(x)`：

`P(A>B) = sigmoid(s(A)-s(B))`

分数只是比较关系的压缩表示。论文主结果以预测人类成对偏好为准，不以绝对分数相关性替代。

### 3.2 ABCDF 等级与内部连续分

部署输出采用 ABCDF，内部保留校准后的 0–100 连续分。A 是真正的顶级档，范围刻意较窄：

| 等级 | 暂定内部区间 | 操作性解释 |
|---|---:|---|
| A | 92–100 | 顶级：在盲评中对高质量锚点保持稳定优势，核心环节几乎无明显短板 |
| B | 80–91.99 | 优秀：整体成熟，有清晰优势，局部问题不损害主要体验 |
| C | 65–79.99 | 合格：叙事目标成立，但存在多处可感知缺陷 |
| D | 50–64.99 | 较弱：部分成立，需要较大修改才能形成稳定阅读体验 |
| F | 0–49.99 | 未达标：核心叙事目标未成立，需结构性重写 |

这些区间是产品显示的初始方案，不是天然真值。正式实验在开发集上结合人类等级锚点、偏好概率和保序校准冻结阈值；测试集不得再调阈值。必须报告 A 档占比，防止等级膨胀。

### 3.3 固定核心维度与开放扩展维度

不尝试预先穷举情感、句式、音律、意象、心理等所有审美维度，也不允许模型在测试阶段任意发明评价标准。采用“稳定骨架 + 数据驱动扩展”的分层设计：

- 固定核心维度：叙事连贯与因果、人物动机与变化、语言与叙述声音、情感/审美效果；
- 开放扩展标签：节奏、句式、音律、意象、氛围、心理可信度、视角控制、新颖性等；
- pilot 阶段对人工比较理由做开放编码与聚类，只有达到预注册频次、评分者一致性和增量解释力的标签才能进入正式扩展表；
- 正式测试前冻结标签表。总体偏好不等于维度等权求和，维度只解释“为什么”。

### 3.4 证据化评语

评语是辅助输出和有效性证据，不是主任务。最少包含：总体等级、最关键的 1–3 个维度、对应原文证据、主要优势/问题和可操作修改方向。不得输出没有文本依据的“更自然”“更生动”等套话。

## 4. 数据设计：把来源与质量真正拆开

### 4.1 数据来源与目标规模

采用双池协议。Pool A 混合已有数据集中的人类与机器文本，只用于训练、开发、去偏和阈值选择；Pool B 由我们先冻结写作 Prompt，再让人类作者和 API 模型根据同一 Prompt 独立写作，只用于最终实验，绝不进入模型训练。仓库现有反向 Prompt 数据属于 Pool A 工程 pilot，不是 Pool B 金标准。

Pool A 初步目标为 1,000–3,000 篇有效训练文本和 3,000–10,000 个训练/开发 pair。Pool B 先用 20–30 个新 Prompt 做协议 pilot，再根据功效分析冻结约 80–120 个全新 Prompt 的主实验；每个 Prompt 至少 1 名人类作者、推荐 2 人，并覆盖至少 3 个机器生成器家族。所有文本保留 `work_id`、`prompt_id`、`genre`、`source_type`、`generator_family`、长度和采集时间，但这些字段不展示给评分者或质量模型。

外部数据只有人机来源标签时不得把“人类”当质量正例；必须使用原生质量评分/偏好或来源盲化的人类补标。Pool B 的人类偏好标签只用于评价，不用于反向训练或选择 checkpoint。

### 4.2 盲评质量分层

先在不显示来源的条件下，依据独立人类成对比较得到每篇文本的质量后验与不确定性，再构造近似 `2 × 2` 数据块：

- 高质量人类 `H_high`；
- 低质量人类 `H_low`；
- 高质量机器 `M_high`；
- 低质量机器 `M_low`。

高/低不是按来源预设，而是由盲评结果定义。若真实数据中 `H_low` 或 `M_high` 数量不足，应继续定向采集，而不是用来源标签代替质量标签。

### 4.3 配对矩阵

| Pair 类型 | 作用 | 论文地位 |
|---|---|---|
| 同来源高 vs 低 | 验证模型能否识别清晰质量差 | 基础能力 |
| 同质量人类 vs 机器 | 测量来源偏置，不应系统偏向任一来源 | 解耦主检验 |
| `H_low` vs `M_high` | 质量与“人类优先”冲突，模型应选择机器高质量文本 | 最关键反转检验 |
| `H_high` vs `M_low` | 质量与常见来源先验同向 | 阳性对照 |
| near-tie | 测量不确定性与校准，不强迫虚假确定性 | 难例分析 |

跨来源配对尽量匹配题材、提示语义、长度区间和体裁。左右位置随机；同一对换序复测；禁止向评分者透露来源。

### 4.4 人类标注协议

每对依次收集：总体偏好、偏好强度、信心、关键核心维度、可选扩展标签、A/B 的文本证据和一句比较理由。正式研究同时招募普通读者与有文学/编辑经验的评分者，并分别报告群体结果。

质控规则在查看模型结果前冻结：最低有效阅读时长只作联合信号，不单独剔除；重复锚点一致性；换序一致性；复制/空泛理由检查；评分者内异常模式。分歧保留为分布或软标签，不简单伪装成确定真值。

## 5. 数据切分与四类测试集

### 5.1 主切分：未见作品

Pool A 按 `work_id` 分组切分 train/dev，并优先同时按 `prompt_id` 隔离；同一作品的切片、改写、同提示近重复不得跨越边界。Pool B 的 Prompt、作者和文本在模型与协议冻结后新建，整体作为独立测试。跨边界 pair 丢弃。pair-random 只允许用于代码冒烟测试，不能作为论文主要数字。

### 5.2 未见生成器

采用 leave-one-generator-family-out：每次将一个完整生成器家族及其版本留作测试，训练阶段不得出现该家族文本。主论文至少预先指定一个生成器家族作最终 unseen-generator 测试；其余可用于轮换验证。

这一实验只能支持“对所测试未见生成器的泛化”，不能宣称对未来所有模型永久有效。必须同时报告性能下降与置信区间，而不是只报告是否高于随机。

### 5.3 关键反转测试

单独冻结 `H_low` vs `M_high` 集合。只有在人类偏好后验足够明确、且题材/长度可匹配时才纳入。该集合不得参与训练或阈值选择，主指标是模型选择人类共识高质量机器文本的比例。

### 5.4 扩展测试

- unseen-genre：完整留出一个题材；
- near-tie：人类偏好后验接近 0.5；
- time split：较晚采集作品仅用于测试；
- prompt-controlled：相同或语义匹配提示下跨来源比较。

## 6. 质量—来源解耦的主检验

### 6.1 反转准确率

在 `H_low` vs `M_high` 上计算正确选择率、Brier 分数和置信区间。这是最直观、优先级最高的证据：若模型仍偏向人类文本，就说明质量评分受到来源捷径污染。

### 6.2 条件来源差

在人类质量后验、题材、长度和提示近似相同的匹配样本中，估计：

`SourceGap(q) = E[s(x) | human, q] - E[s(x) | machine, q]`

理想结果是在主要质量区间内接近 0。使用匹配/分层回归报告估计值和 bootstrap 置信区间；不得只给不显著的 p 值作为“无偏”证明。

### 6.3 来源泄漏探针

冻结质量模型后，用其表征训练一个单独的轻量来源探针，并报告 AUC。另报告质量残差对来源的可预测性。高探针 AUC 不自动等于质量判断有偏，但若同时出现显著 SourceGap 或反转失败，则构成模型依赖来源线索的证据。

### 6.4 干预与反事实压力测试

构造不改变核心事件和人物动机的受控表面编辑，如去除模板化开头、调整常见生成器连接词或统一标点格式，检查质量预测是否大幅改变。此实验只作压力测试，因为任何改写都可能连带改变真实质量；不能把自动“人类化改写”当作无争议反事实真值。

### 6.5 训练时的抑制策略

先训练不使用来源标签的标准 reward model；再比较重采样/匹配、来源对抗头、group-DRO 或残差正则等解耦方法。来源标签只用于构造集合、诊断和去偏，不作为质量模型的正向输入特征。

## 7. 模型与训练

### 7.1 主模型

编码器或生成式 reward model 输出单一潜在质量效用 `s(x)`，用 Bradley–Terry/序数偏好损失训练。平局对应接近 0.5 的软目标；评分者信心可作为预注册权重。主模型先保证排序与校准，再训练独立或共享编码器的评语模块。

### 7.2 基线

- 随机、长度和可读性启发式；
- 字符 TF–IDF Bradley–Terry；
- 现有“像人分”与人机检测器（负对照，不应成为强质量基线）；
- 开源通用 LLM-as-a-Judge：优先本地 Qwen3-8B 等可复现模型；
- 开源专用 Judge/reward model：如 RISE-Judge-Qwen2.5-7B、Prometheus-2-7B 或服务器已有的 Llama-3-8B reward model；
- 同规模中文长文本 encoder/reward model。

任何 Judge 基线都使用冻结 prompt，在开发集确定后不得针对测试集修改。需要记录模型版本、量化、模板、解码参数和运行硬件。

### 7.3 关键消融

- 去掉跨来源配对；
- 不做质量分层或匹配；
- 单一生成器训练 vs 多生成器训练；
- 标准模型 vs 来源去偏模型；
- 固定核心维度、核心 + 扩展标签、无维度；
- 人类理由、LLM 合成理由和无理由；
- pair-random vs group-disjoint。

## 8. 指标与统计

主要指标按优先级为：

1. group-disjoint 人类成对偏好准确率与 Brier；
2. `H_low` vs `M_high` 反转准确率；
3. 条件 SourceGap 及置信区间；
4. unseen-generator 性能及相对下降；
5. 来源泄漏探针 AUC。

同时报告 log loss、ECE、Kendall tau、Spearman、ABCDF macro-F1、相邻等级准确率和 A 档占比。人类可靠性报告序数 Krippendorff alpha、pair agreement，以及专家/普通读者差异。

所有模型差异使用按作品和提示分组的 bootstrap 95% 置信区间；涉及多个生成器/题材时做多重比较校正。near-tie 必须单列，不得用总体相关性掩盖难例失败。

## 9. 等级、维度与评语如何支持主结论

ABCDF、维度和评语不是额外堆功能，而是三类验证工具：

- 等级校准检验模型输出是否具有可解释的相对位置，尤其防止 A 档泛滥；
- 维度归因检验跨来源判断是否落在真实叙事缺陷，而不是“像 AI”等来源标签；
- 证据化评语让独立评分者验证模型理由是否被原文支持，并帮助定位反转失败原因。

评语盲评指标为证据支持率、具体性、帮助度、错误归因率，以及“模型评语 vs 人类评语”的偏好。评语来源能否被猜出只作次要分析；“猜不出来源”不等于评语正确。

## 11. 预注册成功标准

- 主模型在 group-disjoint 测试上显著优于 TF–IDF，并至少达到最强开源 Judge 基线的同等水平；
- 在预先冻结的 `H_low` vs `M_high` 反转集上显著高于随机，并优于“像人分”负对照；
- 质量匹配后的 SourceGap 绝对值低于开发集冻结容忍阈值，且同时给出等效性区间；
- 未见生成器性能显著高于随机，且相对主测试下降处于预注册范围；
- 来源探针、SourceGap 和反转结果联合解释，不选择性报告其中最好的一项；
- ABCDF 阈值在开发集冻结，A 档占比与相邻等级错误公开；
- 至少 80% 的关键评语证据被独立评分者判为原文支持，且评语帮助度高于只给等级。

若反转或 SourceGap 失败，论文仍可作为“叙事评估器依赖来源捷径”的负结果，但不能宣称已经学到来源无关的审美质量。

## 12. 最小可发表版本与完整版本

### 12.1 最小可发表版本

- 可靠的盲评成对数据；
- 至少 2 个机器生成器家族与足够的 `H_low`、`M_high`；
- group-disjoint、反转测试、条件 SourceGap；
- 一个强开源 LLM Judge、一个专用 reward model、TF–IDF 和像人分负对照；
- 统计置信区间和完整失败分析。

规模不足时应定位为 workshop/short paper，主题是“中文叙事质量评估中的来源捷径与诊断基准”。

### 12.2 完整主会版本

- Pool A 具备规模化、可靠质量监督的外部训练混池；Pool B 具备功效分析支持的自建同 Prompt 冻结实验；
- Pool B 至少 3 个生成器家族，且包含训练中完整未见的生成器家族；
- 冻结的 unseen-generator、unseen-genre 和 time split；
- 专用质量 reward model 与去偏训练；
- 等级校准、证据化评语盲评和专家/普通读者分析；
- 数据、代码、prompt、模型版本和预注册统计可复现。

投稿应定位为 **中文叙事质量 benchmark + 来源捷径诊断 + 偏好学习评估器**，而不是一个评分产品。只要数据设计扎实、反转集有效、强基线完整且结论不过度外推，具有明确的发表可能；真正的难点在高质量人类标注、质量与来源的交叉覆盖，以及未见生成器测试的严格隔离。

## 13. 当前仓库执行顺序

1. 将当前 20 题和仓库旧数据归入 Pool A 工程/训练候选，审计授权、质量监督和元数据；
2. 接入多个外部人类/机器数据集，只有可靠质量标签或盲评补标可训练质量模型；
3. 建立 Pool A group-disjoint train/dev，训练标准 reward model并比较来源去偏版本；
4. 用 Pool A dev 冻结 checkpoint、ABCDF 阈值、Judge Prompt 和统计代码；
5. 设计 20–30 个全新 B1 Prompt，让人类和 API 模型按相同 Prompt 写作，只校准实验流程和功效；
6. 冻结 B2 Prompt、长度层、生成参数、seen/unseen 生成器和标注协议；
7. 采集 80–120 个全新 B2 Prompt 组并完成盲评；
8. 在 B2 上一次性运行解耦、反转、未见生成器、校准和评语忠实度实验，结果不回流训练。
