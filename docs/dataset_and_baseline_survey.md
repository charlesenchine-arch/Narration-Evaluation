# 数据集与基线调研：中文叙事质量评估

更新日期：2026-08-20

## 结论先行

现有项目的 600 条 `rating_set.jsonl` 适合做界面、标注流程和模型训练的 pilot，但不能单独支撑论文中的“泛化到未见作品/未见生成器”结论。正式实验应组合三类资源：

1. 自建同提示中文叙事对，用于受控的人类成对偏好；
2. 可合法复用的公开数据，用于外部有效性；
3. 与训练完全隔离的新作品、新提示和新生成器，用于真正的泛化测试。

## 推荐自建主数据

- 目标规模：第一阶段 800–1,200 篇文本，2,500–4,000 个比较对，每对至少 3 名评分者。
- 文本组成：约 35% 人类公开许可文本、55% 多生成器文本、10% 人工控制的缺陷/反事实文本。
- 同提示设计：每个提示包含人类文本（能取得时）与至少 3 个不同生成器输出；温度、长度预算和提示模板留档。
- 题材分层：现实、悬疑、科幻、历史/古风、家庭、校园等；避免单一网文体裁决定模型表现。
- 质量覆盖：通过预筛选构造高、中、低质量，不用“人类=高质、机器=低质”作为标签代理。
- 必存字段：`id`, `text`, `work_id`, `prompt_id`, `generator`, `genre`, `license`, `collection_date`。
- 评分者字段：匿名 id、专家/普通读者、熟悉题材、评分耗时；论文公开时去标识化。

## 必须报告的基线

1. **随机与长度基线**：验证任务没有被长度、格式或来源线索轻易解决。
2. **现有“像人分”**：作为负对照，检验“像人”是否等同于“质量好”。预计不应成为强质量基线。
3. **字符 TF–IDF + Bradley–Terry**：仓库已实现，作为可解释、低成本的专用 reward baseline。
4. **强零样本 LLM-as-a-Judge**：总体判断 prompt，不提供人工标签。
5. **rubric LLM judge**：总体先行、维度诊断、文本证据；用同一模型对照 prompt 设计影响。
6. **专用 reward model**：中文 encoder/LLM 上用成对偏好训练；与零样本 judge 做成本和泛化比较。
7. **评语生成基线**：比较通用 LLM、rubric judge 和经中文评语数据微调的模型。

LitBench 报告其专用 Bradley–Terry 与生成式 reward model 达到 78% 人类偏好一致率，强通用 judge 为 73%，因此“专用模型是否超过通用 judge”应是核心实验，而不是只报告一个模型分数。

## 论文必须避免的陷阱

- **文本泄漏**：同一作品、同一提示或近重复片段不得横跨训练与测试。
- **生成器捷径**：必须做未见生成器测试，并报告按生成器分层的结果。
- **分数伪精确**：0–100 是校准后的潜在效用，不宣称是文学质量的客观绝对值。
- **只报整体相关性**：[The Progress Illusion](https://aclanthology.org/2025.findings-emnlp.1036/) 表明总体相关性会掩盖能力接近系统上的低可靠性；因此单独报告 near-tie 子集。
- **抹平读者分歧**：同时报告多数共识、评分者一致性和读者群体差异。
- **评语幻觉**：评语必须有文本证据，并由人类单独判断“证据支持率”和“评语帮助度”。
- **许可证不清**：许可证未明确的数据只做本地研究候选，不能随仓库再发布。
