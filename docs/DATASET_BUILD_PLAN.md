# 中文叙事质量—来源解耦数据集构建计划 v1.1

更新日期：2026-08-21
核心决策：**外部混池用于训练与开发；自建同 Prompt 人机组文用于冻结实验，绝不用于训练。**

上位要求：[`DATASET_CONSTRUCTION_REQUIREMENTS.md`](DATASET_CONSTRUCTION_REQUIREMENTS.md)

## 1. 两个数据池完全分工

整个项目分为两个物理隔离的数据池。

| 数据池 | 数据来源 | 用途 | 能否训练模型 |
|---|---|---|---|
| Pool A：外部训练混池 | 已有数据集中的人类文本、机器文本、质量评分或偏好数据 | 训练、开发、消融、阈值选择、来源去偏 | 可以 |
| Pool B：自建冻结实验池 | 我们预先写好 Prompt，人类作者与 API 模型根据完全相同的 Prompt 独立写作 | 论文主实验、来源解耦、反转和未见生成器测试 | **不可以** |

```text
Pool A：外部已有数据集
人类文本 + 机器文本 + 独立质量监督
                ↓
清洗、统一字段、盲评补标、质量/来源交叉配对
                ↓
训练集 ── 开发集 ── 模型与阈值冻结
                              │
                              ▼
Pool B：我们自建的同 Prompt 冻结实验
预注册 Prompt ─┬─ 人类作者独立写作
               └─ 多个 API 模型独立生成
                              ↓
                      人类盲评质量真值
                              ↓
                 只评估，不训练、不调参
```

这比把所有来源混成一个总池后再随机切分更强，因为最终实验中的 Prompt、人类作者、文本和部分生成器都没有参与训练。

## 2. 最重要的标签约束

外部数据集中“人类/机器来源标签”不等于“高/低质量标签”。

外部数据按监督强度分为四类：

| 类型 | 外部数据具有什么 | 在 Pool A 中如何使用 |
|---|---|---|
| A1 | 人类质量分数、等级或成对偏好 | 可直接转换为质量训练监督，核对量表后使用 |
| A2 | 人机文本和相同/相近 Prompt，但没有质量标注 | 先做来源盲化的人类补标，再用于质量训练 |
| A3 | 只有人机来源标签 | 只能用于来源探针、对抗去偏或无监督预训练；不能令“人类胜机器” |
| A4 | LLM Judge 伪标签 | 可作辅助预训练或消融；不能作为唯一金标准 |

禁止把所有人类文本自动配成正样本、所有机器文本自动配成负样本。这样训练出来的是人机检测器，不是质量评估器，也无法通过最终跨来源反转实验。

Pool A 的核心训练 pair 仍应来自来源盲化后的质量关系：

- 同来源高质量 vs 低质量；
- 跨来源、质量差异明确的 pair；
- 跨来源 near-tie；
- `H_low` vs `M_high` 和 `H_high` vs `M_low`；
- 题材、Prompt 语义和长度匹配的 pair。

## 3. Pool A：外部训练混池计划

### 3.1 来源要求

- 至少 2 个人类文本数据来源；
- 至少 3 个机器生成器家族或机器文本数据来源；
- 优先选择自带质量分数、等级、排序或人类偏好的数据集；
- 没有质量标注的数据，只抽取有代表性的子集补做人类盲评；
- 任一单一数据集不能垄断一个质量层；
- 保留 `source_dataset`、`human_source_id` 和 `generator_family`，不得混池后删除来源。

### 3.2 训练池建议规模

第一版建议建立 2,000–5,000 篇外部训练候选，经过授权、完整性、长度、去重和标注筛选后，形成约 1,000–3,000 篇有效训练文本。

训练 pair 不要求穷举。优先构造 3,000–10,000 个信息量较高的 pair，并保证：

- 来源与质量交叉；
- 每个主要质量层覆盖多个数据集；
- 同一作品、Prompt 或近重复簇不跨训练/开发切分；
- 不用 pair-random 作为正式开发划分。

实际规模根据许可、可获得质量标注和计算资源调整。质量监督的可信度优先于总篇数。

### 3.3 外部数据接入流程

1. 记录数据集名称、版本、链接、下载时间和原文件 SHA-256；
2. 核验许可证、署名、训练许可和再分发限制；
3. 保存原始文件，只在派生层进行清洗；
4. 统一字段，但保留原始 ID 和原始标签；
5. 排除残缺切片、非叙事、乱码、助手套话和无法追溯文本；
6. 执行全文 SHA-256 去重、近重复检测和跨数据集重复检查；
7. 将原有质量量表映射到统一内部表示，并保存映射依据；
8. 对无质量标签的关键子集进行人类盲评补标；
9. 构造质量—来源交叉 pair；
10. 按作品、Prompt、来源簇切为 Pool A train/dev。

### 3.4 Pool A 的模型开发边界

以下工作可以使用 Pool A train/dev：

- 选择模型架构和损失函数；
- 训练 reward model；
- 训练来源对抗头或其他去偏方法；
- 选择 ABCDF 阈值；
- 设计评语模块和固定 Judge Prompt；
- 做超参数、消融和错误分析；
- 确定最终 checkpoint。

一旦最终 checkpoint 和协议冻结，不能再根据 Pool B 的主实验结果返回 Pool A 调参后重新报告同一个 Pool B。

## 4. Pool B：自建同 Prompt 冻结实验池

### 4.1 为什么 Pool B 必须自建

Pool B 的作用不是扩大训练量，而是提供最干净的检验：在同一个事先定义的写作任务下，人类和机器分别产出文本，评估器是否按质量而不是来源判断。

自建数据具备外部反向 Prompt 难以同时提供的条件：

- 人类和机器收到真实相同的 Prompt；
- Prompt、长度和生成条件在写作前固定；
- 人类作者和实验文本未参与模型训练；
- 可以保留明确同意、原始提交和时间戳；
- 可以预留训练中未见的机器家族；
- 可以在看结果前冻结分析方案。

### 4.2 Prompt 先冻结，再让双方写作

每个实验 Prompt 在任何人类或机器开始写作前冻结，内容至少包括：

- 宽泛主题或写作情境；
- 体裁要求；
- 固定字符范围；
- 是否需要第一/第三人称等必要约束；
- 人物、冲突、转折和结局由作者独立设计；
- 禁止模仿具体作者或复述已有作品。

人类和机器应收到相同的核心 Prompt。不能先看人类成文，再给机器追加更精确的字数、情节或修改要求。

为控制长度，建议在 Prompt 产生前随机分配长度层，例如 600–750、750–900、900–1,050 字；人类与机器共同遵守同一层。最终阈值在 pilot 后冻结。

### 4.3 人类组文

- 每个 Prompt 最少 1 名人类作者，推荐 2 名独立作者；
- 同一作者不宜完成过多 Prompt，避免作者习惯替代“人类来源”；
- 招募普通写作者、有经验写作者和少量专业作者/编辑，保留自然质量差异；
- 明确禁止生成式 AI 代写；拼写检查等辅助必须声明；
- 作者看不到机器输出和其他作者输出；
- 保存原始提交，不由研究团队文学润色；
- 保存作者同意、训练/公开许可、AI 辅助声明、原文哈希和提交时间；
- Pool B 授权书要明确：文本仅用于评价实验还是也允许公开，但无论许可如何都不用于本项目模型训练。

身份或写作经验只用于分层分析，不直接作为质量标签。

### 4.4 API 机器组文

每个 Prompt 至少分配给 3 个独立生成器家族。API 仅接收与人类相同的核心 Prompt，不接收人类原文。

建议同时包含：

- 训练数据中出现过的生成器家族，用于 in-domain 对照；
- 至少 1 个 Pool A 中从未出现的完整生成器家族，用于 unseen-generator 主测试。

统一要求：

- 全新上下文；
- 不使用搜索、工具、记忆或人工追问；
- reasoning 设置作为独立条件固定；
- 固定 temperature、top-p 和 max tokens；
- 保存请求模型、实际返回模型、日期、API base、request ID 和 token；
- 保存拒答、截断和越界输出；
- 采用预注册的最大重试次数和“首个合格输出”规则；
- 不从多个结果中人工选择最好的一篇；
- API Key 只存系统钥匙串或环境变量，不进入仓库和日志。

执行顺序：连接检查 → 每模型 5 个 Prompt 冒烟 → 小批校准 → 冻结参数 → 正式批量生成。

### 4.5 Pool B 的人类盲评

模型预测之前或之后可以收集人工标签，但评分者必须不知道来源，模型和分析者不得根据这些标签继续训练主模型。

每个 pair 依次收集：总体偏好、强度、信心、核心维度、可选扩展维度、原文证据和比较理由。

建议：

- 每个核心 pair 至少 5 名评分者；
- A/B 位置随机；
- 10%–20% 的 pair 做换序复测；
- 普通读者和文学/编辑经验评分者分层报告；
- 用成对比较模型估计质量后验和不确定性；
- 形成 `H_high/H_low/M_high/M_low/near_tie`，但这些标签只用于 Pool B 评估分析。

### 4.6 Pool B 绝对禁止事项

- 不进入 reward model、评语模型或来源去偏模型的训练；
- 不用于 checkpoint 选择、早停、超参数或 ABCDF 阈值选择；
- 不根据结果改 Judge Prompt 后继续报告同一测试集；
- 不把失败样本删除后重新定义主结果；
- 不将看过结果的 pilot Prompt 与正式 Prompt 混为同一冻结测试；
- 不把最终测试文本加入下一轮训练后仍称为同一个 held-out benchmark。

若未来确实想将 Pool B 用于训练，必须把它改名为旧训练数据，并重新采集一个从未见过的 Pool B v2。

## 5. 三层实验结构

为了避免在最终测试集上边看边改，自建部分再分为三个不重叠的层次：

| 层次 | 建议规模 | 用途 | 是否进入模型训练 |
|---|---:|---|---|
| B0 工程冒烟 | 5 个 Prompt | 检查招募、API、前端和字段 | 否 |
| B1 协议 pilot | 20–30 个 Prompt | 冻结长度、评分指南、重试和样本量方案 | 否 |
| B2 最终冻结实验 | 初步建议 80–120 个 Prompt | 论文主结果 | **绝不** |

B0/B1 可以用于改实验流程，但不能用于训练质量模型，也不能混入 B2 主结果。B2 的最终规模应结合 B1 的人类一致性、效应大小和功效分析决定。

如果资源有限，B2 每个 Prompt 可先采用 1 名人类作者和 3 个机器家族；更稳健的方案是每 Prompt 2 名人类作者，以降低单一作者能力和偶然状态的影响。

## 6. 冻结顺序

在采集 B2 前，必须冻结并保存哈希：

1. Pool A 训练/开发切分；
2. 最终模型 checkpoint；
3. ABCDF 阈值和所有校准参数；
4. 评价器输入模板和 Judge Prompt；
5. B2 Prompt 列表、长度层和排除规则；
6. API 生成条件和重试规则；
7. 人类盲评指南与评分者剔除规则；
8. 主指标、置信区间和统计脚本；
9. seen/unseen 生成器家族划分。

冻结完成后再采集 B2 人类与机器文本。若发生模型下线等不可控变化，按预注册规则新建版本并记录，不能静默替换。

## 7. 论文主实验如何跑

Pool A 训练完成并冻结模型后，在 Pool B2 上运行：

1. **总体质量预测**：模型对所有文本输出内部效用、ABCDF 和评语；
2. **人类偏好一致性**：预测 Pool B2 的盲态人类成对偏好；
3. **同 Prompt 人机比较**：在相同任务和长度层下比较来源；
4. **质量反转**：重点报告 `H_low` vs `M_high`；
5. **同质量来源差**：控制人类质量后估计 SourceGap；
6. **未见生成器**：完整报告 held-out generator family 的性能下降；
7. **位置和表面干预**：换序、格式统一和必要的压力测试；
8. **理由有效性**：盲评模型引用证据和评语是否被文本支持。

论文不能只报告“机器赢了多少次”。需要回答：在独立人类质量真值下，模型是否选择了质量更好的文本，以及这种能力是否受来源和新生成器影响。

## 8. 外部混池特有的防捷径规则

Pool A 的风险是模型把“哪个数据集”当成质量。

因此要求：

- 保留 `source_dataset` 和 `generator_family`，但质量模型正文输入不可见；
- 运行人类来源与机器家族多分类探针；
- Pool A 开发阶段做 leave-one-human-source-out；
- 各质量层覆盖多个外部数据来源；
- 标题、字段残留、特殊标点和平台套话不进入模型正文；
- 同一数据集、作者、作品和 Prompt 不跨 train/dev；
- 最终 Pool B 完全由新 Prompt 和新作者构成，作为对数据集文风捷径的外部检验。

来源探针很强不自动等于质量模型有偏，但如果来源与质量层绑定，训练协议必须先修复。

## 9. 建议的数据量与判断量

### 9.1 Pool A

| 内容 | 初步建议 |
|---|---:|
| 外部原始候选 | 2,000–5,000 篇 |
| 有效训练文本 | 1,000–3,000 篇 |
| 训练/开发 pair | 3,000–10,000 个 |

### 9.2 Pool B2

以 100 个 Prompt、每 Prompt 1 名人类作者和 3 个机器家族为例：

| 内容 | 数量 |
|---|---:|
| 人类文本 | 100 |
| 机器文本 | 300 |
| 总文本 | 400 |
| 同 Prompt 人机 pair | 300 |
| 每 pair 5 人的基础判断量 | 1,500 次 |

若每 Prompt 使用 2 名人类作者，则有 200 篇人类文本和 600 个基础人机 pair，能更可靠地分离作者个体差异，但招募与标注成本约增加一倍。

## 10. 当前数据重新定位

当前 20 个外部人类文本及其反向 Prompt、Gemini 和 DeepSeek 输出不属于最终 Pool B，因为人类文本不是根据我们预先冻结的真实 Prompt 写成。

它们应归入：

- Pool A 的候选训练/开发材料；或
- 工程诊断集，用于验证生成脚本、来源探针和 Judge 基线。

在补充独立质量标注前，当前人机来源关系不能直接成为质量训练标签。现有代理 Judge 的结果可用于诊断，但不能替代 Pool A 的可靠质量监督，也不能作为 Pool B 的论文主结果。

## 11. 当前下一步

1. 为 Pool A 建立外部数据集清单，优先寻找带质量分数、排序或偏好标注的数据；
2. 将现有 20 题标为 `pool_a_engineering_pilot`，不再计划进入最终实验集；
3. 确定 Pool A 中哪些样本已有质量监督、哪些需要盲评补标；
4. 用 Pool A train/dev 完成模型、阈值和去偏方法选择；
5. 设计 B1 的 20–30 个全新 Prompt，并在写作前冻结长度层和规则；
6. 招募人类作者完成 B1，同时通过 API 让 3 个生成器家族完成相同 Prompt；
7. 用 B1 只校准实验流程和正式样本量，不训练主模型；
8. 冻结 checkpoint、协议和统计代码后，采集 80–120 个全新 B2 Prompt 组；
9. B2 只用于一次性主评估和预注册的补充分析。

最终论文的证据链是：**模型只在外部混池中学习，最后面对从未见过的 Prompt、作者、文本和至少一个新生成器，仍能按照盲态人类质量判断做出正确选择。**
